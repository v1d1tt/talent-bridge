# Slice 04: Admin reference page + import of the old CSVs

**What was built:** the admin's **reference register** (`/admin/references`). The admin tags a pro clip (player, shot, camera view, handedness, source) and picks the clip. The browser reads it with the **same slice 3 pose code** as an athlete's clip and draws only the stick figure. The server stores the pose sequence as a **reference** and recounts the **shot gate** for that shot + view in the same transaction. The page shows the shot gates (references per shot + view, with a "needs 3+" mark) and the register (one ruled row per reference, each with a link to its stick figure).

A one-time command, `cmd/import-legacy`, imported the 12 pose CSVs of the 2026 hackathon build. Measuring them showed they are not comparable with browser references, so they are stored as **old CSV references** that are drawn but **not counted** toward a gate ([ADR 0008](../adr/0008-import-old-csvs-as-legacy-references.md)).

No picture of a pro clip is stored or shown anywhere: pro footage is not ours to keep.

## 1. The flow, file by file

**Adding a reference (browser → server)**

1. **`/admin/references`** → [pages/References.tsx](../../web/src/pages/References.tsx). `AdminOnly` shows the page only to the admin; anyone else gets a plain sentence, and the page makes no admin request. The server checks again on every route, so the page check is only for the reader.
2. **`AddReference`** is a small state machine: `idle → loading → reading → read → saving → saved`, or `failed`. Picking a clip runs `openClip` → `loadLandmarker` → `extractPose` ([pose/extract.ts](../../web/src/pose/extract.ts)): the slice 3 path, unchanged. Unlike the athlete page, the `<video>` is never put on the page: only the canvas with the stick figure. When reading ends, the shared **`Plate`** ([pose/Plate.tsx](../../web/src/pose/Plate.tsx), moved out of the result page) shows the figure with a frame slider, so the admin can check it before saving.
3. **Submit** reads the tags from the form with `FormData` (Solid 2 applies signal writes on the next tick, so the form is the source of truth at submit time) → **`createReference`** ([references.ts](../../web/src/references.ts)) → `POST /api/admin/references` with the CSRF header.
4. **`Guard(Roles(admin))`** ([internal/auth/access.go](../../internal/auth/access.go)): signed in, CSRF token, admin role.
5. **`reference.Service.Create`** ([internal/reference/reference.go](../../internal/reference/reference.go)): `MaxBytesReader` (4 MiB → 413), `DisallowUnknownFields` (a stray `"video"` → 400), then **`Add`**:
   - `Input.check`: view and handedness are enums; player (1-80) and source (1-500) are plain text on one line, with no control characters and no text-direction controls; **`pose.Validate`** (the same checks as an athlete's sequence → 422 with a reason).
   - `GetShotByCode` → 422 `unknown_shot` if the code is not in the list.
   - `pose.Encode` (TBP1, the slice 3 format).
   - One transaction: **`LockShotGate`** (`SELECT … FOR UPDATE` on the gate row) → `CreateReference` → **`RecountShotGate`** (`count(*)` of browser references for that shot + view).
   - `created_by` comes from the auth session and `origin` is always `browser`; the request body cannot set either.
6. **201 `{"id"}`** → the page bumps a version signal, and the gates and the register load again.

**Reading**

- `GET /api/admin/shot-gates` → `ListShotGates`: one row per shot + view, browser references counted, old CSV references counted apart.
- `GET /api/admin/references` → `ListReferences`: the register, **without** pose sequences (they are 10-25 KB each).
- `GET /api/admin/references/{id}` → `GetReference` → `pose.Decode` → [pages/ReferenceView.tsx](../../web/src/pages/ReferenceView.tsx) draws the figure.

**The import (once)**

`cmd/import-legacy` → for each of the 12 tagged files: `legacy.Read` → `legacy.Convert` ([internal/legacy/legacy.go](../../internal/legacy/legacy.go)) → `reference.Service.Add` with `origin = legacy_csv`. The same `Add` as the API, so the same checks and the same gate rules apply.

## 2. The schema (migration 00004)

| Table | What it holds |
|---|---|
| `shots` | the 15 shots the owner approved: 3 bowling (`fast_bowling`, `off_spin`, `leg_spin`) and 12 batting. A left-handed player uses the same shot; handedness is its own tag. |
| `pro_references` | shot, view, player, handedness, source, `origin` (`browser` / `legacy_csv`), fps, frame count, the compressed pose sequence, `created_by` |
| `shot_gates` | one row per shot + view (30 rows, seeded): `reference_count`, `lopo_passed`, `lopo_run_at`, `enabled` |

Two rules live in the database itself, so no code path can break them:

- `CHECK (NOT enabled OR (lopo_passed AND reference_count >= 3))`: a gate cannot be switched on without 3+ references and a passing leave-one-pro-out test (slices 5-6).
- A **partial unique index** `ON pro_references (source) WHERE origin = 'legacy_csv'`: the import can run twice and adds nothing the second time (`ON CONFLICT … DO NOTHING`).

## 3. Why a stored count, recounted under a row lock

The PRD keeps `reference_count` on `shot_gates`. A stored count can drift from the rows it counts. Two choices keep it right:

- **Recount, do not increment.** `reference_count = (SELECT count(*) …)` is correct whatever happened before; `+ 1` would carry any earlier error forward.
- **Lock the gate row first.** Postgres runs at READ COMMITTED: each statement sees the data committed when it starts. Without the lock, two admins saving at the same moment could each count before the other commits, and both would write the same number. `SELECT … FOR UPDATE` makes the second transaction wait at its first statement; its recount then starts after the first one committed and sees both rows. `TestConcurrentReferencesAreAllCounted` saves 6 references at once and checks the count went up by 6. Removing the lock made that test fail in the mutation pass.

## 4. The old CSVs: measure before you trust

The slice brief guessed the files held "15 joints, probably hip-centred world coordinates". The measurements said otherwise (full table in ADR 0008):

- **Hip midpoint exactly (0, 0) in every row** → the script subtracted it. Both image and world landmarks could look like that.
- **Body size changes 3.7 times between files** → not metres. World landmarks give a person about the same size in every clip; image coordinates change with the camera zoom.
- **13 joints, 15/25/30 fps, dropped frames, two files over 10 s, all bowlers filmed front-on.**

So the converter puts x and y back into a 1280 × 720 picture (hip midpoint in the middle), keeps visibility, drops z, writes world values as 0, and marks the 20 missing landmarks as **not measured** (all six values 0). The stick figure skips segments with a not-measured end (`drawnSegments` in [pose/skeleton.ts](../../web/src/pose/skeleton.ts)); a landmark the model simply could not see is still drawn dashed. Dropped frames are filled by linear interpolation on a uniform time grid, and files over 10 s keep their last 10 s (the delivery is at the end).

## 5. Security

| Threat | Control | Test |
|---|---|---|
| A non-admin calls an admin route | `Roles(admin)` on all 4 routes; the route × role table | `TestRouteRoleTable`, `TestOnlyAdminsGetIn`, Playwright "an athlete cannot open the register" |
| Cross-site POST | CSRF token | `TestStateChangesNeedTheCSRFToken` (missing and wrong token) |
| SQL injection | sqlc: parameters only | a player named `' OR 1=1--` is stored as plain text |
| Script in a source URL | Solid escapes text; only http(s) becomes a link, with `rel="noopener noreferrer nofollow"` | Vitest: `javascript:alert(1)` stays text |
| A name that reads backwards (U+202E) | text-direction controls refused | `TestBadReferencesAreRefused` |
| A video or picture rides along | `DisallowUnknownFields`; the reference service has no Blob Storage at all | 400 `bad_json` test; Playwright checks no `<img>`/`<video>`, only this app's host, no clip bytes |
| Body sets `created_by` or `origin` | both are set by the server only | the field is not in the request struct |

**Mutation check:** 17 rules were broken on purpose, one at a time (admin-only routes, unknown fields, body cap, pose validation, control characters, player length, the view enum, the forced `browser` origin, browser-only counting, the recount, the row lock, the idempotent import, http(s)-only links, the not-measured skip, the hip centring and the last-10-s trim). A test failed for every one.

## 5b. Follow-up: the plate zooms to fit

On the live page the old CSV figures filled only about a third of the plate: their x and y keep the zoom of the broadcast video. `fitView` ([pose/skeleton.ts](../../web/src/pose/skeleton.ts)) finds the box around every measured point of the **whole sequence** (cut to the video frame) and returns one zoom `k` and centre; `fitFrame` moves each measured point by `(x - cx) * k + 0.5`. Three choices:

- **One view per sequence, not per frame.** A per-frame zoom would make the figure grow and shrink as the slider moves, and hide a run-up.
- **The same `k` on both axes.** x and y are fractions of the video's width and height and the canvas has the video's aspect ratio, so one `k` keeps the body's shape.
- **Not-measured landmarks stay all 0.** Moving them would make `measured` true and draw lines to the corner.

The `Plate` is used on the athlete's result page too, so browser figures also get bigger, unless the person already fills the video. Tests: `skeleton.test.ts`, "the plate zooms to fit".

## 7. Questions an interviewer could ask

**Q: Why not just add 1 to `reference_count` when a reference is saved?**
A: An increment is only as right as every earlier write, and it needs a decrement everywhere a reference could ever be removed. A recount is right by construction. Under READ COMMITTED a recount alone can still lose a concurrent insert, so the transaction first locks the gate row with `SELECT … FOR UPDATE`; the second writer waits, and its recount sees both rows. A test saves 6 at once to prove it.

**Q: You had 12 pro sequences already. Why do none of them count?**
A: Because I measured them. They are hip-centred image coordinates with an unknown aspect ratio, no world positions, 13 of 33 points and mixed frame rates. A score against them would mix two measurement systems, and the leave-one-pro-out test might pass on numbers that only look comparable. They are stored and drawn for the record, marked `legacy_csv`, and the gate counts only browser references. The fix is cheap: re-create the references from clips on the admin page.

**Q: How do you stop pro footage from leaking, when the admin uploads pro clips?**
A: Structurally: the clip never leaves the browser (the same pose code as athletes), the admin page never even puts the video on screen, and the reference service has no Blob Storage client, so there is no code path that could store a picture. The API refuses unknown fields, so a picture cannot ride along in the JSON. A Playwright test checks that no request carries clip bytes and that the page has no `<img>` or `<video>`.
